## 1. Q0P-1 (HIGH): each v2.2 checker's contract is bound

**Defect.** R4's round compared only checker names and the count against the v2.2 record. Measured by the verifier:
changing `tests/v2/fixtures/known_bad/b1_bindings.json` `"expect"` to `""` makes the named-reason check vacuous,
because `""` matches every problem. The real writer then wrote a 57/57 record and the restricted sealing job was green.
The same edit fails v2.2.0's own gate.

**Rule** (`validation/v23/q0_round.py::contract_problems`, run by `problems`, so by `--write`, by `--check` and by
`Q0RoundV23`'s first test). For every checker of the v2.2 record:

* `package`, `fixture` and `expected` in round v2.3 equal the v2.2 record's (`CONTRACT`);
* the known-bad fixture file in the tree has the LF bytes v2.2.0 (`da3ea33f`) committed. A CRLF checkout is the same
  bytes. A missing file is named. If the v2.2.0 objects cannot be read (a shallow clone), every fixture is named
  "unreadable (fail closed)".

There is no exception list. Changing a contract needs a new `q0_round.py`, which `V23_PINNED` pins. That means a new
wiring patch and a new owner ruling, which names the contract delta it accepts.

**The delta the owner reviews.** `--write` and `--check` print `delta(result)`: every field that round v2.3 changes
against the v2.2 record, checker by checker (`+` a new checker, `-` a missing one). The owner reviews these lines, not
a new record of 910 lines.

**Planned edits, re-read.** No planned W1 fix edits a fixture file. The b1 `kernel=` fix (W1-DESIGN.md:292) and the
execution_order `at=` fix (:293) change `checker_calibration.py`'s calls, not the fixtures, so the contract rule does not
block them. A fixture or expected-reason edit by any lane keeps round v2.3 red until a new ruling.

**Residual, the same as v2.2.** A checker's code can still be weakened while it fails its unchanged fixture for the
named reason. That is Q0's own limit, the same in v2.2. The replay runs v2.2.0's own code.

## 4. Q0R-INT-1 (MEDIUM): a merge or a shallow clone no longer hides a rewritten draft

**Defect.** `reviewed_draft` listed the commits that added the draft without `--full-history`. A merge that resolves
the draft to a rewritten version hides the reviewed add commit from the default history simplification. The round
then opened on unreviewed content that carried the reviewed draft's name. The verifier showed this for a conflict
resolved by hand and for a clean `-X theirs` merge. A `--depth 1` clone hid it the same way.

**Fix** (`tests/v23/test_v23_rounds.py`):

* `reviewed_draft` refuses a shallow repository (`git rev-parse --is-shallow-repository`).
* It lists the add commits with `--full-history`.
* Every git call there runs with `GIT_NO_REPLACE_OBJECTS=1`.
* The rule itself is unchanged: HEAD's blob must be the blob of every commit that added the draft.

**Regressions** (`tests/v23/test_v23_seq13_wiring.py::LedgerSeq13`):

* the conflict resolved by hand and the `-X theirs` merge are refused;
* a merge that leaves the draft alone opens;
* a full clone opens and a `--depth 1` clone is refused.

**For the owner.** R4 told the owner to recompute the digest at HEAD with `ledger_digest.py`. R5 names
`reviewed_draft`, which refuses a rewritten draft before it digests it.

**Corrected residual** (the original amendment's §5, fourth bullet). A merge rewrites no history, so it was never
covered by "a history rewrite of the draft". It is now refused. What remains undetectable in-tree is owner words the
owner did not write, or a rewrite of the repository's history itself.

**Defect.** R4 named `Q0-1-V23-ROUND.md` by path only, on the reason "a sha256 of it here would be a hash cycle".

After approval it could be edited, delta table and residuals included, with no check turning red.

**Fix.**

* R5's decision gets `BOUND_SHA256`, a map from path to LF sha256. It holds both Q0-1 amendment pages (the original at
  `0e0d0fbf822861134a073dac7da1be3ae2b2329c77ebf803ab7774809a7f8178`, and this one) and the eight evidence files of
  `docs/v2.3/evidence/round-auth/` and `docs/v2.3/evidence/q0-round/`.
* `ledger_seq13_problems` keeps the round closed while any of these files is not exactly those bytes: edited, moved or
  deleted. A CRLF checkout is the same bytes.
* The parity page is the only page named by path alone, for the reason stated (it quotes the digest).

**Regressions** (`LedgerSeq13.test_every_bound_file_must_stay_as_reviewed`):

* an amendment edited after approval is refused, naming the file;
* an evidence file deleted after approval is refused, naming the file;
* a CRLF checkout of every bound file opens.
