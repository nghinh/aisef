## Standard used

An entry is **PROVEN** only if both of these hold:

1. A committed, contemporaneous artifact names the OS with a platform-unique token.
2. The artifact binds that OS to the measurement run that produced the entry's committed bytes, either by naming the
   target or through an explicit run→target list.

These do not bind:
* a sibling run or a failed attempt;
* the session host;
* a record builder's `sys.platform`;
* commit prose;
* co-occurrence in a commit.

Absence of a marker is never used, as the task requires.

**Intro commit.** For each entry, its intro commit was located: the first commit on HEAD's ancestry whose record file
holds a canonical-JSON-identical entry, using the same `canonical()` and sha256 as the engine. All 327 were found,
across 24 intro commits from 2026-09-21 to 2026-10-01. The record bytes at HEAD equal those at `da3ea33f`.

**Runner bracket.** The runner committed at an intro commit is not necessarily the one that measured its entries
(`affae7da` holds entries with a key its own runner never writes). Each row therefore carries `runner_bracket`: the
committed runner versions whose output keys match the entry (`killed_by_timeout` from `2f7f93bc`, `strays_reaped` from
`cfe14c03`), and whether the runner comment is in all of them.

## What the engine would need (not done; it needs an amendment and an owner decision)

1. **A new tier D after W in §2.4.3.** Today §2.4.3 explicitly lists commit messages, code comments, co-occurrence and
   worker-directory names as "not evidence". Admitting any of D1–D3 changes the evidence rule, the same kind of change
   as I8. It needs its own `docs/v2.3/amendments/<ID>.md` and an owner ruling, and it must not be a silent engine edit.
   OT additionally needs the out-of-tree files committed and digest-pinned; even then they are not W evidence, because
   W reads only committed `mutation-workers` histories at the basis.
2. **Intro-commit and runner-bracket derivation inside the engine.** For each legacy entry, the engine re-derives the
   first ancestor commit whose record holds a canonical-identical entry, and the runner versions its keys allow, at
   every check. A shallow clone gives `UNRESOLVED`.
3. **A sha256-pinned pointer set, never a free-text search at check time.** Each pointer is (commit, path, JSON pointer
   or line, exact token, blob sha256), as in `legacy-platform.json` `pointers` (26 verified pointers: 19
   bound by blob sha256, with the token checked inside the value at the JSON pointer for JSON records; 7 commit-message
   pointers bound by commit id). The set is pinned in the engine by digest, as the I8 ruling is. The engine verifies:
   * the blob bytes (or the commit id);
   * the token;
   * that the commit is an ancestor of the basis;
   * for D1, that commit = the entry's intro commit, and that the pointer names the target's module path;
   * for D2, that the entry's runner fingerprint matches the runs the pointer names;
   * for a session statement, that it was first committed no later than the entry's intro commit.
4. **A closed OS-token grammar** applied to the exact token (macOS / XNU / darwin / launchd / `com.apple.` and the
   §2.4.3 darwin path tokens → posix·darwin; Linux / ubuntu / `/usr/lib/python3.N/` / `/home/<u>/` / `/root/` →
   posix·linux; Windows / `<tree>\` → windows). A negated statement carries no grammar token and assigns nothing.
   Contradiction keeps today's semantics over every pointer attached to the entry, session statements included: any
   pointer of the other family, or both flavors, gives `INVALIDATED (I6: contradictory)`. The table above is computed
   this way.
5. **Labelling.** `platform.by = "OT"|"D1"|"D2"|"D3"`, and the flavor is printed as a hint. The flavor is never "proven"
   without a run-bound pointer. D3 rows print flavor "unproven"; the 38 rows with no contemporaneous hint print
   family "unproven" too. The report must not say "Linux" for any of them (§2.4.2).
6. **A scope check against the claim.** All 327 have `C(t) = posix`. None is one of the 3 Windows liveness targets.

Without that ruling, §2.4.5's default stands: re-measure the 327 (W1-DESIGN [E] 16.2–182.5 serial-h), or use the
owner-only I8 ruling "platform-unbound v2.2.0 currency". Committed tier D at its strongest (D1) covers 4
entries / 34 mutants; D1+D2 covers 6 / 138, with a weakened
binding. The out-of-tree OT lead covers 49 / 1,806 and names the producing run, but only an
owner ruling plus committing and pinning the files could admit it. Admitting session-level hints under the proposed rule
resolves none of the rest. Any wider tier is an owner ruling in evidentiary form, not a reconstruction.
