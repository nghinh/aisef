**Status.** Implemented under "AISEF V2 — WP-6.3 EXECUTION AUTHORIZATION / OLD-PATH REMOVAL / NO DUAL AUTHORITY /
P6 CLOSURE". Evidence: `closure-evidence/v2/P6-AUTHORITY-INVENTORY.json` (generated by
`validation/v2/old_path_audit.py --generate`, checked in both directions by `--check`) and
`closure-evidence/v2/P6-OLD-PATH-REMOVAL.json` (builder `validation/v2/p6_evidence.py`, `--check` twin). Tests:
`tests/v2/test_old_path_audit.py` (the audit on synthetic trees: every disposition, every direction it fails closed in,
every static proof — the mutation kill tests) and `tests/v2/test_no_dual_authority.py` (the real tree: the inventory

## 1. What "one authority" means here

Exactly one control path decides a story: `aisef2/orchestrate/story_runner.py::run_story`. The audit establishes
this mechanically, not by grep:

* **Reality on the V2 side** is every function of `aisef2/` and `validation/v2/` that appends a control event
  (`GATE_DECISION`, `STORY_COMMIT`, `STORY_RETRY`, …), calls a control function (`gate.decision`, `budget.charge`,
  `admit_story`, `prove`, …), constructs a control type, or is a projection's `step` — found by AST with imports
  resolved (relative imports included), plus import-graph reachability from `run_story`.
* **Reality on the V1 side** is every module of the frozen control plane (`aisef/control/`, `aisef/phases/`,
  `aisef/cli/`), every named former gate/judge/qualification symbol, and every other module of `aisef/` whose
  definitions carry control vocabulary — each with a definition digest, so a row goes stale when a module's shape
  changes and a symbol becomes `REMOVED` when it no longer resolves.
* **The inventory** classifies every row into one of the five closed dispositions; anything else is
  `UNCLASSIFIABLE` and fails the audit. The committed inventory is compared with reality in both directions:
  an authority in the tree with no row, a row with no authority, a disposition that moved, a digest that changed,
  a legacy reference in a runtime or checker tree, an adapter that imports V1 — each fails `--check`.

| tree | rows | disposition | why |
|---|---|---|---|
| `aisef2/` (runtime) | 64 | ACTIVE_V2_AUTHORITY | control-capable functions; each row records what it draws on and whether `run_story` reaches it |
| `aisef2/orchestrate/seam.py` | 5 | COMPATIBILITY_NONAUTHORITATIVE | the seam, under measured conditions (§3) |

| `tests/v2/p4/test_process_table.py` | 2 | HISTORICAL_ONLY | a P4 reproducer imports two V1 modules (`clients.base`, `harness.process_owner`) |

script, which is not a V2 entrypoint.

## 2. The six proofs

Each is an exact boolean in the record, `static` from the audit and `runtime` from the named test; the property is
the conjunction.

| proof | static | runtime |
|---|---|---|
| NO_OLD_GATE_AUTHORITY | no legacy reference in `aisef2/` or `validation/v2/`; every `aisef/` row UNREACHABLE or REMOVED; 0 UNCLASSIFIABLE | every V1 family raises at import (meta-path finder) and at call (already-imported symbols patched); three real ORCH fixtures (commit, conflict, outage-retry) give the byte-identical control chain poisoned and unpoisoned |
| NO_DEVELOPER_TEST_PRODUCT_AUTHORITY | no name bound from an engineering-quality call is an argument of a product call; `aisef2/quality/` names no product-truth symbol; kernel rules NO_RAW_VERDICT_ROUTING, RESULT_ONLY_THROUGH_BINDING, NO_VERDICT_FROM_ABSENCE_DECLARATION | five developer-test variants (PASS, FAIL, VACUOUS, IRRELEVANT, INCOMPLETE) give one identical product proof |
| NO_PARENT_DEVELOPER_EXECUTION | `assess` follows the verifier checkout's move to the candidate; admission receives no developer-test input; the seam names no quality type; kernel rules CANDIDATE_ONLY_EXECUTION, NO_DEVELOPER_ARTEFACT_AT_PARENT | exploding tests at the parent are never imported, collected or executed (a mark file they would write never appears) |
| NO_RECENCY_EVIDENCE_SELECTION | no control module imports wall-clock time or directory listing, reads `Event.time`, a file time, a listing, a recency ordering key, or names `HEAD` (the journal writers may stamp `time`) | two records, the newer wrong: the cited record decides; with the clocks reversed the decision is the same, and two records without a citation refuse |
| NO_SIDE_RETRY_COUNTER | kernel rules NO_SIDE_RETRY_COUNTER, RETRYABLE_ONLY_IN_TAXONOMY | a corrupted reporting counter changes nothing; a corrupted journal budget changes the decision exactly as the projection says |
| ALL_CONTROL_DECISIONS_JOURNAL_BACKED | in `_attempt` every gate row follows its stage's typed call, every row is the argument of `checks.append`, one decision cites the list, retry follows `budget.charge` | the decision → source-seq table of a committed and a rolled-back story: every decision rests on journal facts that precede it |

**The gate-row citation, read exactly.** `gate/check` carries no `source_seqs` in any journal format (its schema in
`aisef2/journal/event.py` declares no citation, and formats 2 and 3 inherit it); adding one would be a format change,
which V2-005 freezes. R6 is therefore read as: each gate row follows the typed event of its stage within the same attempt, and
`gate/decision` cites every row by seq. The decision table makes that mechanical from the journal alone.

## 3. The seam stays, as a non-authority

`aisef2/orchestrate/seam.py` is classified COMPATIBILITY_NONAUTHORITATIVE only while all of these hold, measured on
every `--check`: it imports nothing of `aisef`; it constructs only V2 inputs (`ObligationRole`, `Polarity`,
`SubjectAbsence`); it names no engineering-quality type; it refuses a `HUMAN_DECLARATION_REQUIRED` row; and
`run_story` calls it before its first journal event. The migration-table generator is classified the same way while
it imports nothing of `aisef`, reads V1 as text only (`ast.parse`, never an import) and emits
`HUMAN_DECLARATION_REQUIRED` instead of inferring. Break any condition and the row becomes UNCLASSIFIABLE.

## 4. Fail-closed, both directions

Measured in `test_old_path_audit.py` and, on the real tree, `test_no_dual_authority.py::Inventory`:

* an unenumerated authority (a new module appending `GATE_DECISION`; a new `aisef/control/` module) fails;
* a stale row (an id that resolves to nothing) fails, as does a moved disposition, a changed kind, a changed shape;
* a dual-authority fixture — a V2 function that also names a V1 gate — fails even when both would agree;
* a legacy fallback (`try: v2 except: v1`; `if v2_unknown: return legacy_result`) fails;
* an adapter that imports V1 fails; a test module importing V1 must be enumerated as HISTORICAL_ONLY.

## 5. Decisions the owner should see

* **No edit to `aisef/`.** The authorization allows one only when an old authority is reachable and cannot be
  neutralized elsewhere; none is reachable. The V1 product tree is the one the P5 seal bound.
* **The V1 console script is UNREACHABLE, not REMOVED.** `pyproject.toml` still declares `aisef = aisef.cli:main`;
  removing it would edit the frozen V1 release surface. It is not a V2 entrypoint, V2 declares no console script,
  and the V2 tree never imports `aisef`.
* **Nothing new in V2-005's vocabulary.** No event type, failure code, owner, journal format or projection was added
  or changed; format 3 stays 29/29 and the nine codes exact.
* **Two P4 tests import V1.** `tests/v2/p4/test_process_table.py` reproduces a V1 defect against the frozen V1
  modules; it is HISTORICAL_ONLY, enumerated, and the test tree is not a runtime authority path.
