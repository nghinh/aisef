# Dogfood, 2026-09-13 — two projects run through the framework end to end

Two fresh projects, both driven by OpenCode on the `mycombo` alias
(MiniMax 2.7 — not a frontier model), both starting from nothing but a
`docs/requirements.md` written by hand:

| Project | Shape | Why this shape |
|---|---|---|
| `todo-oc` | Quick Notes — one `index.html`, localStorage, no build step | a browser surface: screens, mockups, e2e, accessibility |
| `todo-cli` | Taskbook — a terminal todo list, Node, JSON file | no graphical surface at all: unit tests only |

The point of the exercise was not to ship two todo apps. It was to read, at
every step, **what the framework extracted against what the agent actually
wrote** — and to fix the differences.

## 1. What the runs reached

| Phase | `todo-oc` (browser) | `todo-cli` (CLI) |
|---|---|---|
| project-context → PRD → architecture → ux | ✅ | ✅ |
| epics → stories (with the size-gate retry) | ✅ 7 stories | ✅ 5 stories |
| mockups | ✅ 1 screen, contract with 3 components | ✅ declared headless, empty contract |
| readiness | ✅ | ✅ |
| first story | ✗ (0/6 criteria had tests) | ✗ (three attempts, see below) |

The CLI story came closest on its third run, after the lint and planning
fixes: `test`, `lint`, `write scope`… `criteria have tests`, `coverage 100%`
and `real tests` all green, stopped by four checks — a path traversal the
security reviewer found (`../../../etc/passwd` canonicalises through
`resolve()`, then `saveStore` writes and renames onto it), a help text of four
lines where the criterion says one, tests that were green on their first run,
and four files written outside the write scope **because the story's own
criterion demanded them** — which is bug 114, found by that failure.

Both projects planned cleanly and neither shipped a story. The gates that
stopped them were right to: on `todo-oc` no acceptance criterion had a test
(`0/6`), and on `todo-cli` the reviewer found weak assertions in the tests the
agent wrote and the security reviewer found a path traversal. The blocker in
both cases is the model, not the harness — which is the honest reading of a
run driven by a deliberately non-frontier model, and the reason the numbers
below are about defects found rather than stories shipped.

## 2. Twenty-seven defects, found by running

Numbered as in `FAILURE-TAXONOMY.md`, where each one carries its symptom,
root cause, lesson and regression test.

### Silent losses in the planning parsers (88, 89, 91, 92, 93, 94, 98, 105, 111, 114)

Eight of the twenty are the same shape: the agent wrote something correct, the
framework read something less, and nothing went red.

- **91 is the one that mattered.** Blocked for writing nine acceptance
  criteria in one story, the planner did not split the story — it chained the
  scenarios as `**And** **Given** …`. The parser reads a criterion as starting
  at `**Given**`, so six scenarios became one, the size gate passed, and the
  story file handed the agent a single `AC-…-1` covering all six, which the
  behaviour ledger can mark VERIFIED on the strength of the first. A gate that
  counts parsed output makes the parser part of the gate, and this is the
  format an agent found *while being blocked*.
- **93**: `AD-2 — Binds: NFR-1, NFR-3` parsed to an empty list (`\bFR-` does
  not match inside `NFR-`), and an empty list did not trigger the
  "binds nothing, so binds everything" fallback either, because bindings
  *were* declared. The two decisions that defined the project — the
  localStorage key every note is stored under, and the 500 ms UI budget — were
  injected into no story's prompt.
- **105** stopped a pipeline outright: told to split, the agent rewrote its
  headings as `### Story 01-01:` — the same spelling the framework uses for
  story ids everywhere — and eleven stories across seven epics disappeared
  behind "no readable stories found in epics.md".
- **111 is 91 again, one keyword over.** Having taught the parser that
  `**And** **Given**` opens a new criterion, I left `**And** when …` alone —
  and the CLI plan came out with exactly one criterion per story, including
  stories that plainly describe two scenarios. Patching the example rather
  than the case.
- **114 is the most expensive one, and the last found.** A story's acceptance
  criterion named four `lib/commands/*.js` files outside its write scope. The
  check for exactly that exists — and filters backticked paths by proximity to
  a mutation verb, from a table holding nineteen Vietnamese verbs and the word
  `commit`. On an English project it matched nothing, so the check was off,
  not weaker. The stories gate approved the story; the guard blocked the
  writes three attempts and about twenty agent sessions later. A keyword
  heuristic is a heuristic *per language*, and 2 400 unit tests stayed green
  because none of them was written in English.
- **98/106** are a pair worth reading together: attaching a component table
  that names no screen to every screen fixed a single-screen document and
  broke a six-command one, where it put every story over the size limit.
  Widening a match widens everything that counts its results.

### Fail-open paths (96, 100, 104)

- **96**: the mockup agent marked `<section data-state="primary">` with
  `data-annotation`, the extractor subtracted the whole subtree, and the design
  contract came out with **zero components** for a screen that has a textarea,
  an Add button and a search box. Nothing failed — an empty component list is
  a warning, and mockup-map compares an empty contract against anything and
  passes. Deleting the commitments leaves by the PASS door.
- **100**: every failed tool call became a guard message, so `guard_blocked` —
  "the agent tried to do something forbidden" — was set by `File not found:
  index.html`. It reaches the evidence, the acceptance report and the
  benchmark's guard counts.
- **104**: the acceptance report's top table showed ✅ Test Evidence for
  requirements the same report scored `AC w/ Test 0/6`, in a story that failed.

### Messages that sent the reader the wrong way (90, 97, 102, 103, 112)

- **102**: a story ended with "recurring infrastructure error: the session
  wrote nothing (17 turns)". The `infra` flag is correct accounting — a session
  with nothing to grade must not consume a quality attempt — but it was also
  read as the diagnosis, pointing at the provider for a model outcome.
- **97**: the readiness gate printed "configure `app.dev_command`" ten lines
  above "✅ 7 stories are all executable", because the first came from a record
  written before mockups existed.
- **103**: a project that had just enabled `--experimental-test-coverage` was
  told to add `--coverage`.

### Credential and environment (99, 101)

- **101**: `ANTHROPIC_` sat in the shared env allowlist, so an OpenCode session
  meant to run through the project's own router received the host's Anthropic
  key — and a client that reads such a key uses it *instead of* its own login.
  This does not fail; it shows up on someone else's invoice.
- **99**: three red Windows CI runs traced to `text=True` without an encoding:
  the child speaks UTF-8, the parent decodes cp1252, the reader thread dies
  inside `communicate()`, and `stdout` comes back `None` — indistinguishable
  from a program that printed nothing.

### The framework measuring its own footprint (109, 110, 113)

- **113** failed a story's lint check with 116 `no-undef` errors, every one in
  `.claude/skills/*/scripts/*.cjs`. The framework installs 155 skills there
  and requires the project to commit them, so every linter the project
  configures reads them. What the framework makes a project carry, the
  framework answers for.
- **109**: `detect()` read a freshly created Node project — one source file —
  as brownfield with 216 source files and Python as its main language. 213 of
  them were the skills `aisef setup` had just installed under
  `.claude/skills`. A survey of a project has to subtract the surveyor. The
  skip list also existed in two copies, and the copy the baseline walked was
  the unfixed one.
- **110**: planning reads `docs/requirements.md` and nothing else, so a
  repository that already has files gets planned as though the directory were
  empty. The CLI project's first story was "Initialize Node.js project
  structure", its acceptance criterion opening "Given a fresh directory with
  no files", for a repository whose `package.json` already had every field it
  asked for. Its tests were green at the parent SHA, the nop control refused
  them exactly as designed, and three attempts went into finished work. The
  brownfield mechanism existed; nothing pointed at it, and a greenfield
  baseline said only "no source code yet" instead of naming the manifest.

### Scope of the framework itself (107)

The ux step required a screen inventory from *every* project, so a CLI had its
six commands mapped onto six screens and every story carried a browser,
mockup-map and accessibility contract. A project can now declare
`**Screens:** none — no graphical surface`. A UI project that merely forgot
its table is still an error — which is why the document declares it rather
than the gate inferring it from an empty list.

## 3. What the framework got right

Worth recording, because a bug list reads like an indictment:

- Every gate failure in both projects was **honest and actionable**. No gate
  passed on absent evidence; `guard ran` recorded `not applicable` rather than
  a pass when hooks were not compiled; unconfigured verification kinds were
  recorded as unconfigured, never as green.
- The **cut-session retry** works: the OpenCode client could not parse the
  model's tool call twice in one attempt, both were classified `infra`, both
  retried, and the third session completed the work.
- The **split-retry loop** worked exactly as designed on both projects: the
  size gate blocked, the epics phase re-ran with the gate memo, and the second
  pass came back within limits.
- The **approval records** carry the truth: `auto-approved (--auto-approve);
  BMAD reported partial with 2 open questions`, SHA-bound, with machine checks
  attached.
- The **independent reviewer earned its cost** on the CLI project. Against a
  weak model it found, unprompted: `JSON.stringify(this)` in the task store
  serialising `save` and `load` to `null` (the store breaks after one
  save/load cycle); a `catch` swallowing `EACCES` and corrupt JSON along with
  the intended `ENOENT`; `assert.ok(stdout.length > 0)` passing for any
  non-empty string; and an `includes('empty') || includes('list')` where the
  criterion says both. The **security reviewer** separately found a path
  traversal: a custom store path written without validation, then atomically
  renamed over the target.
- The **nop control** (ADR-005 V3) refused tests that were green without the
  story's code — "still green without story code (parent SHA 08bb71c)" — for
  tests asserting `package.json` fields that already existed.
- The **stuck detector** stopped a story after two attempts blocked for the
  same reason, instead of spending the third.
- **Rule drift: none.** Re-scoring every recorded attempt with today's code,
  after twenty-six changes, reproduces every recorded verdict check by check
  (`aisef replay --all`).

## 3b. Two things worth watching, not yet fixed

- **A single fat acceptance criterion is invisible to the size gate.** The CLI
  project's first story carried one criterion that required six files, four
  `package.json` fields and a lint config. `story.max_acceptance_criteria`
  counts criteria, so one counts as one; the complexity score agrees. The
  reviewer caught the under-delivery on the first attempt, which is the system
  working — but the gate that exists to size stories saw nothing. A length
  heuristic would catch it and would also be a heuristic, so it is recorded
  here rather than shipped.
- **Story worktrees inherit the host's MCP servers.** A `.serena/` directory
  appeared inside a story worktree during the browser run, written by an MCP
  server configured globally on the machine. It is ignored by the scope
  checks (`HARNESS_OWNED`), so nothing broke — but the OpenCode adapter has no
  equivalent of Claude Code's `--strict-mcp-config`, and a session's tool set
  therefore depends on the operator's machine.

## 4. What this does and does not establish

**It establishes** that twenty-six real defects were sitting in the framework
where only a full run would find them. Eighteen had been through the unit
suite — 2 400 tests, green — without being touched, because they live in the
join between what an agent writes and what the framework reads, and a fixture
written by the same hand that wrote the parser never disagrees with it. Two
projects, one day, one model.

**It does not establish** that the framework can carry a project to
production with a non-frontier model. Neither project shipped a story. Each
was stopped by a gate that was right to stop it, and in both cases the work
that was missing was the model's: acceptance criteria without tests, tests
whose assertions pass on anything, a path traversal in a fifty-line store.

**It does not measure quality of outcome at all.** Nothing here is a
benchmark; the C-1 and C-1b cohorts are, and they say what they say
(`docs/BENCH-REPORT-C1.md`, `docs/BENCH-REPORT-C1B.md`).

The next honest step for the framework is a run on a model that can clear
these gates, to find the defects that only appear *after* a story merges —
the ledger, preservation across stories, the improve loop, pre-deploy. Those
paths remain unexercised by this exercise, and saying so is part of the
result.
