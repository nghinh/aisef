"Need judgment? Use the model.

The gap

Coding agents are powerful.
But power without discipline is risk.

Self-grading

The agent grades its own work

Most frameworks let the model decide when it's done. That's asking the student to grade their own exam. When reviewer and developer are the same session, mistakes become invisible.

Detached evidence

"Tests passed" proves nothing

A test that ran on a commit three edits ago says nothing about the code you're shipping. Evidence without a commit hash is an anecdote, not proof.

Trust by default

The client is trusted blindly

A hook pointing to a missing binary means no guard ran — silently. Most frameworks assume if the guard is configured, it ran. AISEF checks whether the guard actually executed.

No discipline

Uncontrolled writes, unclear scope

Agents write wherever they want. Without write-scope enforcement and blast-radius analysis, "fixing" one module silently breaks three others.

Trust chain

From requirements to verified software

One input file drives every phase. The candidate is frozen at a commit SHA. Everything after the freeze is deterministic code, not model judgment.

Left of the line
The model uses judgment: planning, coding, problem-solving.
Frozen SHA
The candidate commit is immutable. No further edits.
Right of the line
Deterministic code: tests, review, gates, evidence. No model opinion.
Core differentiators

What the harness guarantees

Each mechanism exists because a real agent run exposed the gap it fills.

  • SHA-bound evidence

    Every check is tied to the exact commit it ran on

    Evidence from a different SHA is classified as stale — a distinct state from failure and from success. No retroactive claims.

  • Reviewer ≠ developer

    The review session is a separate agent, forbidden to edit code

    Structural guarantee, not a prompt instruction. The model never supervises its own output. It is a separation guarantee, not a safety net — the measured miss rate below says the machine checks are what hold.

  • Qualified gates

    16 story-level checks, each with positive, negative and environment controls

    48 total controls. "Is the gate itself scoring correctly?" is answered by a command, not by hope. Since 1.6.0 the reviewer's own judgement is scored the same way — 6 judgement classes × the same 3 controls, 18 more cells.

  • Write-scope lock

    Each story declares which files it may touch

    The guard rejects any diff that changes files outside scope. Blast-radius analysis on brownfield codebases. An agent that "fixes" module A doesn't silently break modules B, C, D.

  • Nop detection

    A test already green before the story wrote code proves nothing

    The gate compares test results against the parent commit. No credit for pre-existing passes. Red-before-green is checked.

  • Six outcomes

    PASSED · FAILED · UNRUNNABLE · UNCONFIGURED · WAIVED · N/A

    Unconfigured ≠ passed. Unrunnable ≠ failed. Three invariants that prevent silent elision of missing checks.

  • Behaviour ledger

    Every requirement, acceptance criterion and screen has a tracked state

    VERIFIED, GAP, or REOPENED. The ledger is rebuilt from evidence — never a second source of truth. Regression is automatic.

  • Crash recovery

    Reconcile-on-start with three recovery scenarios

    Roll-forward for merged work, undo for in-progress, stale cleanup for abandoned state. Every aisef run starts with reconciliation.

Benchmark honesty

What we've proven — and what we haven't

Honest framing builds more trust than inflated claims. Here's exactly where the evidence stands.

● Measured and verified

  • On simple bug-fix tasks, correctness was saturated for both harnessed and bare agents. On the hard tasks with a non-frontier model, the corpus cannot currently detect a difference at all: across 339 recorded attempts, 12 of 340 cross-arm pairs (3.5%) came out differently, and 25 of the 30 tasks never separated the two arms even once. C-1b's published +0.06 does not survive re-reading — all three of its failing attempts were sessions the CLI cut, and under the attempt definition its own protocol pre-registered, all three tasks read 1.00/1.00 in both arms. So no correctness claim is supportable, in either direction
  • The harness is not free, and the price is measured rather than asserted: the harnessed arm spent 44% more turns in C-1, 27% more in C-1b, and 1.51× the tokens in C-2 — for the same outcome each time. aisef cost attributes spend to outcomes and reports that only 4–22% of it bought an attempt the gate passed
  • Conformance probes pass 10/10 on two different clients (Claude Code, OpenCode)
  • And the result that does not flatter the harness: cohort C-2, pre-registered before any data, came back inconclusive — 11 of 12 tasks saturated at the ceiling with the unharnessed arm at 36/36, so the experiment had no power to resolve the comparison at that model and task difficulty. Three cohorts, three different signs (−0.06, +0.06, −0.028); quoting one without the others would be selection, not evidence
  • 3,122 unit tests cover all public modules; 411 benchmark attempts across 30 challenge tasks (the majority on real agents, the rest on a simulator that says so)
  • The review layer is measured too, and the numbers are not flattering: false block 10.5% (6 of 57 blocks, stated as a floor rather than an estimate), miss 34–39% (27 of 70 passes), and of 20 consecutive reviews of an identical tree, 11 reversed the verdict. Recomputable from evidence on disk, with no model call
  • The framework's own project-closure gate (aisef closure, 27 criteria in 6 gates, read from evidence on disk with no model call) passes 24 of 27 on 1.7.2; the three open criteria are external validation. A defect in that gate itself — release identity conflated with the repository HEAD, so recording evidence about a release invalidated it — was measured on 1.7.1, fixed in 1.7.2 and pinned by a permanent fixed-point test
  • Crash recovery: three interrupted-run paths (journal reconcile, run loop, improve loop) plus a real SIGKILL mid-write — at most the one half-written line is lost

● Not yet proven

  • That the harness helps an agent solve more — four cohorts, four nulls. The measured value is elsewhere: refusing to call unfinished work done, and leaving evidence why
  • No external user has independently adopted the framework — all evidence is internal. External validation of the public 1.7.2 release (closure gate G6) is in the hands of an external participant with a frozen instruction bundle; until their report is in, this line stands
  • Distributed execution (multi-machine) is designed but untested in production
  • Local sandbox provider does not isolate credentials — Docker is required for credential-sensitive projects
  • Performance at scale (50+ stories, large codebases) is untested

Six harness groups. Everything in the framework belongs to exactly one. This is also the acceptance yardstick for the framework itself.
